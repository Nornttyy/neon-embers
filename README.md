# 霓虹余烬 · Neon Embers

一款零依赖的 HTML5 Canvas 俯视角动作游戏网站。玩家操控科技小球，球体会实际持有弧光剑、相位双刃或动力锤，并通过武器旋转完成三段挥砍；同时支持轨道手枪、闪避、正面格挡、精准招架和角色技能。当前版本是固定流程的单机动作闯关，支持桌面键鼠、移动端触屏、本地存档和离线安装。

## 操作

- `WASD` / 方向键：移动；鼠标：瞄准。
- `1`：选择球体核心近战槽；`2`：选择轨道手枪槽。鼠标滚轮累计到切换阈值后也会在两槽间切换，同一次滚动手势只切换一次。每次开始新任务默认选择槽 1。
- 鼠标左键：使用当前武器槽；选择槽 2 后直接朝鼠标方向射击。`J` 保留为当前武器的键盘辅助操作。近战槽可进行三段连击；相位双刃会由两把独立武器交替挥动，第三击交叉斩击。
- 按住鼠标右键或 `E`：格挡与精准招架。键盘、鼠标和触屏防御会分别记录，松开其中一个不会提前取消仍由另一个来源保持的防御；`K` 不绑定动作。
- `Space`：闪避；`R`：在已装备的非空技能槽之间循环；`Q`：释放当前技能。当前每个球体只在技能槽 1 装有一个核心技能，槽 2、3 为后续扩展预留，按 `3` 不触发动作。
- 触屏“攻击”按钮使用当前武器槽，“远程”按钮保持为不切槽的轨道手枪快捷射击，“技能”按钮释放当前技能。
- 击败敌人会掉落回收能源。每关开始前会进入固定整备房间，可以购买装甲修复、弹匣、体力电池和应急护盾；商品不会随机刷新，战斗中也不会出现随机强化、三选一或临时构筑。

近战显示使用真实武器图片的逐帧挥动，不以扇形色块或覆盖角色的大月牙图片代替。挥砍包含蓄力、快速命中和回收阶段，并支持提前输入下一段连击；动作在 8～10 个关键姿态之间按时间连续插值，武器运动与实际碰撞始终来自同一姿态。攻击有效阶段会沿实际刀刃端点绘制实时动态刀光，轨迹每帧跟随武器姿态；双刃的两把武器拥有彼此独立的轨迹。刀光不使用静态 PNG，不重复绘制半透明武器当作残影；真正接触敌人时仍显示刀刃、双刃或重锤命中反馈。武器在所有攻击和强化阶段保持固定尺寸，范围强化只扩大挥击角度。伤害按照画面中刀刃或锤头的实际接触位置结算，不再使用角色前方的抽象扇形范围。挥空使用真实物体高速掠过空气的呼啸采样，敌人受击统一使用短促的手枪弹丸撞击采样；金属声只用于格挡和机械装填。战斗音乐采用 136 BPM 的鼓点、低音和合成旋律。敌人生成会根据当前同屏数量自动放慢，避免小场地持续堆满敌人。

0.9.0 将战斗中可辨认的反馈全部换成同一画风的透明 PNG 素材：持续防御、格挡命中、精准招架、破防、临时护盾、三种技能、双方弹丸与枪口、四类武器命中、敌人挥击/突进/生成/护盾/销毁、能源拾取、硬边闪避拖尾和首领爆发都有独立图片；疾行体和突进体也不再靠基础敌人改色。Canvas 用每类 8～10 个关键帧参数动态插值位置、旋转、缩放与透明度，形成连续动画，同时保留真实武器和投射物碰撞。这里不使用视频纹理：关键帧驱动更容易保持透明背景、动作同步和网页端体积稳定。

0.9.1 删除了玩家挥砍过程中的刀光、刀尖轨迹和半透明武器残影；攻击时只绘制当前姿态下的真实武器，实际接触敌人后才显示命中反馈。全部战斗特效会在进入整备房前以互不重叠的隐藏网格预绘到游戏主画布，并分别提交普通与发光混合管线，提前完成浏览器首次纹理上传，避免防御、招架或命中特效第一次出现时产生明显卡顿。

0.9.2 恢复了早期的程序动态刀光：画布每帧从真实武器碰撞形状取刀刃端点，再连接最近的采样点形成快速淡出的轨迹。双刃分别采样、分别绘制，刀光不会把两把刃连在一起。本版未恢复已退役的 `slash-arc.png` 或任何大月牙贴图，也不使用半透明重复武器图片制作伪残影。挥空不会新增贴图特效，武器接触敌人后的命中反馈保持不变。

0.9.3 为固定的核心近战武器和轨道手枪加入两个可见武器槽。数字键 `1`、`2` 只选择槽位，不会立即攻击或消耗弹药；鼠标左键使用当前槽，选择手枪后会朝鼠标方向射击，`J` 仅作为同一主攻击的键盘辅助操作。`Q` 不再承担射击功能；触屏“远程”仍保留独立射击入口。攻击、格挡、闪避、破防或技能动作期间的切换会排队，角色回到空闲状态后才应用，避免显示武器、刀光和碰撞判定在动作中途错位。HUD 始终只高亮一个槽，新任务默认槽 1。

0.9.4 明确分开武器、技能与防御输入：`1`、`2` 直接选择两把武器，纵向鼠标滚轮使用 48 像素累计阈值并按 160 毫秒手势窗口防抖，横向滚动和缩放手势不会误切；`R` 只在已装备的非空技能槽间循环，`Q` 释放 HUD 唯一高亮的当前技能。技能数据保留三个可扩展槽与独立冷却，当前任务只装配球体核心技能，空槽不会被选中或施放；未来加入多技能时无需更改输入模型。`E`、鼠标右键和触屏格挡采用独立来源集合，只有全部释放后才结束防御。持续按键不会重复切槽或反复施法，`K` 与 `3` 均无战斗绑定。

0.9.5 新增六张同画风透明事件素材：第三段连击命中使用 `combo-finisher.png`，精准招架使用 `parry-counter.png`，三类核心技能启动使用 `skill-core.png`，闪避结束使用 `dash-arrival.png`，终结击杀使用 `execution-burst.png`，方向性命中碎片使用 `impact-shard.png`。前五种爆发反馈通过至少 10 帧的 `impactSnap10` 时间曲线叠加在原反馈之上，不替代真实武器、碰撞和基础命中素材；移动火花与碎片使用 10 帧 `sparkFlight10`，拥有真实速度、阻力、旋转和命中方向。`energySpark` 与 `impactShard` 交替生成，同屏合计最多 48 个，避免用无限粒子制造卡顿。挥空仍只显示程序动态刀光，不会生成任何贴图命中特效。

0.9.6 新增两张全屏透明反馈素材：青紫色 `screen-success-overload.png` 用于闪避落点、第三段连击、技能启动、精准招架和胜利，红紫色 `screen-danger-fracture.png` 用于处决、受伤、破防、首领登场和致命伤害。普通显示使用 10 帧 `screenPulse10`，开启“减少闪光”后改用单峰后持续衰减的 10 帧 `screenPulseReduced10`；减闪模式的边缘素材强度最高 0.1、全屏底色最高 0.02，并且最终比例不会超过正常值的 24%。加载阶段按 10 类事件分别生成普通与减闪版本，共 20 张 512×512 RGBA 合成精灵；每张精确保留该事件的底色/边缘强度比例，运行时只需一次 `source-over` 全屏绘制，原素材、10 帧缩放/旋转/透明度曲线和 1.12 倍过扫描都不变。两类反馈只占用一个 `screenFlash` 状态：同类事件 160 毫秒内不重复，全局 340 毫秒内不反复起闪；冷却中的高优先级事件沿用原对象和已经播放的归一化进度，也不会重启全局冷却。精准招架优先级 94，高于处决的 92，因此处决不能盖掉仍在显示的招架反馈。普通攻击命中和普通非处决击杀仍只显示局部命中、碎片和音效，不会让整个屏幕闪烁。

屏幕素材在运行时使用 1.12 倍过扫描并围绕画面中心轻微缩放、旋转，避免动画边缘露出空白；预热按主画布 1.24 倍尺寸居中提交，覆盖动画的最大外扩。全尺寸提交失败时该素材会从已预热集合删除并记录失败，不能把未上传纹理误报为就绪。清关房间和结算界面使用 0.3 秒渐入，前 38% 保持透明，让末击、处决或胜利闪屏先完整显示，再出现面板。

首次进入会显示轻量 CSS 加载画面，进度来自已完成加载与解码的真实素材数，随后依次标记 14 张角色缓存、20 张全屏合成精灵以及 `source-over`、`lighter` 和 `screen` 三种主画布特效管线的预热状态；这些运行时素材完成后即可结束初始加载。选择球体进入整备房时，任务加载层还会等待战斗音频采样和当前房间的完整场景缓存，二者完成后才取消输入拦截。这个过程只提前准备原有高质量素材和混合模式，不会通过降低分辨率、减少帧数或删除特效换取流畅度。

受击高亮、玩家闪避亮度和技能高饱和外观会在加载阶段按原图尺寸预先生成缓存精灵，战斗帧只绘制已完成的缓存，不再临时运行 `CanvasRenderingContext2D.filter`。动态刀光同样不使用实时阴影模糊：单剑/双刃使用 17 像素透明外层和 3 像素高亮内层，动力锤使用 24/4 像素两层轨迹，由 `lighter` 混合形成稳定光感。这些优化移动了计算时机，没有削减刀光宽度、玩家状态反馈或素材清晰度。

地板、约 80 个静态场景物件和带阴影的边界不再每帧重绘。每个整备房/战区在进入前以当前 DPR 绘制到单个全场景 Canvas，四周额外保留 160 像素透明边距，避免裁掉边界 PNG 和阴影外溢。屏幕尺寸、DPR、房间或关卡变化时会先生成新缓存，提交到主画布后再交换并释放旧画布；缓存失败时仍使用完整场景绘制兜底。

性能结论来自 Chrome 151、Apple M5 Pro Metal、120 Hz、1280×800 实测：稳定基线 p50/p95 为 8.3/8.4 ms；修复前受击、闪避和 420 px `screen` 特效分别达 16.7、18.1 和 16.6 ms，击杀后连续 3～4 帧为 16.7 ms，逐段 `shadowBlur` 刀光达 33.3/25.1 ms。单独停止场景重绘后，同样事件立即回到 8.3～8.4 ms，证明根因是每帧静态场景阴影已吃满帧时余量，运行时 `filter` 和刀光阴影只是进一步放大卡顿。采用全 DPR 场景缓存、全尺寸预滤镜精灵和无阴影动态刀光后，刀光、受击、闪避和 `screen` 分别为 8.3/8.4、8.3/7.3、8.3/8.4 和 8.4/8.3 ms；击杀后 49 帧 p95/最大值为 8.4/8.4 ms，超过 12 ms 的帧数为 0。全部特效数量保持不变。

0.9.5 在同一 Metal GPU 路径、1920×1200 主 Canvas 下补测新增叠层与粒子：资源 58/58、VFX 34/34、预滤镜精灵 14/14 全部就绪；连段终结与处决、精准招架、技能核心、闪避落点以及 48 个移动粒子的首次和连续触发最高帧间隔均不超过 9.3 ms，超过 12 ms 或 20 ms 的帧均为 0。粒子更新最高 0.1 ms，两层特效绘制最高 1.9 ms，没有通过降低贴图尺寸、帧数或数量换取结果。

0.9.6 的性能验收继续使用完整分辨率、36 项 VFX、20 张全屏合成精灵和 48 个移动粒子，不允许通过缩小素材、减少关键帧或降低粒子上限通过测试。`npm run perf:gpu` 会启动独立的 headed Chrome，确认 Metal、1920×1200 主 Canvas 和 120 Hz 路径后，分别测量青紫成功闪屏、红紫危险闪屏以及危险闪屏叠加 48 个移动粒子；无动画帧时会在 45 秒后失败并自动清理浏览器。Apple M5 Pro / ANGLE Metal 最终复验基线 p50/p95 为 8.3/8.4 ms，成功与危险闪屏均为 8.3/9.2 ms，危险闪屏叠加 48 个移动粒子为 8.3/8.8 ms，相对基线 p95 最大增量 0.8 ms，所有场景最大帧不超过 9.4 ms，超过 12 或 20 ms 的帧均为 0；`renderScreenFlash` CPU p95 为 0.1 ms。普通 headless smoke 使用软件路径，只验证行为和真实图片绘制，不用不稳定的软件帧间隔冒充 GPU 性能结论。

离线安装保留全部 94 项公开资源，并继续使用固定 4 路队列。Service Worker 会同时等待窗口 `load` 事件和 `game.assetsReady`：只有冷启动的 60 张运行时图片完成加载、解码，14 张角色缓存和 20 张全屏合成精灵完成生成与主画布预热，以及 36 项 VFX 在 7×6 网格中完成主画布预热后才开始注册，彻底隔离两批请求的带宽竞争。两张全屏源素材还会以主画布 1.24 倍尺寸居中独立提交：成功素材走 `screen`，危险素材走 `source-over`，每次提交后各等待三帧；运行时使用的 20 张合成精灵则通过独立 `source-over` 网格一次性上传。安装随后在后台继续，不再成为初始画面或开战流程的门槛。核心 HTML/CSS/模块失败会终止该版安装，单个可选图片或音频失败会记录但不阻断其他项；页面仍通过 `CACHE_PROGRESS` 接收真实完成数。带内容版本的 URL 允许复用 HTTP 缓存，不再强制重新下载同一内容。

当前美术统一采用石墨黑与深海军蓝装甲、青色边光以及按职能区分的高饱和能源核心。剑锋、相位、壁垒三种玩家球体和八类敌人拥有独立透明 PNG 机体；整备房商品、能源终端、电力柱、障碍、通风装置以及房间、外围、封锁区和核心区地面也使用同一套绘制素材。开战前会等待全部战斗图片完成加载与解码，临时失败会自动重试；只有连续失败才回退到简化 Canvas 几何图形。玩家身体与武器始终分离渲染，武器仍按独立握点和碰撞体完成真实挥砍。

普通与重型敌人的攻击预警使用不同的定向素材并按 8～10 个关键帧推进，不再显示程序扇形；初始校准、备用装甲和回收协议三张永久升级卡也使用带版本号的同画风图片。

任务采用真正的清关推进：`1-1 外围突破`清除基础近战敌人，`1-2 火力封锁`加入远程、护盾、重装与精英组合，`1-B 核心决战`迎战最终首领。选择球体后先进入整备房间，购买固定补给并手动开始战斗；清除本关固定敌人后自动回收地面能源，再返回同一个房间准备下一关。下一关在房间内只显示为“下一战”，不会提前加载敌人或切换当前关卡，必须再次点击开始按钮才会激活。房间不会免费恢复生命，玩家也可以不购买任何物品直接出发。流程没有随机敌群、无限刷怪或局内随机强化；局外装备校准也不会改变武器尺寸。

## 本地运行

```bash
npm start
```

浏览器打开 `http://127.0.0.1:4173`。保持终端运行，按 `Ctrl+C` 停止服务器。

## 生成可部署网站

```bash
npm run build
```

命令会生成 `dist/`。把 `dist` 目录中的全部内容上传到任意支持 HTTPS 的静态网站托管服务即可。网站不依赖数据库或服务端运行时。

构建时会根据全部公开文件自动生成内容版本号，并写入脚本、样式、图片和音频 URL。Service Worker 更新后会自动完成一次缓存穿透刷新，因此替换同名素材不需要玩家手动清缓存。

本地检查生产目录：

```bash
npm run preview
```

## 验证

```bash
npm run check
npm run smoke
npm run perf:gpu
```

`check` 运行语法、动作配置和网站资源测试。`smoke` 使用本机 Chrome 验证开局、真实武器接触判定、关卡推进、能源回收、Boss 和结算流程；`perf:gpu` 使用带界面的 Chrome 验证真实 Metal GPU 帧预算。两个浏览器命令都需要先运行本地生产预览服务器。

## GitHub Pages

仓库包含 `.github/workflows/deploy-pages.yml`。推送到 `main` 后，GitHub Actions 会先运行完整检查，再自动构建并发布 `dist/`；检查失败时不会覆盖线上版本。`dist/` 是生成物，不提交到源码仓库。仓库只需一次性在 Settings → Pages 中将构建来源设为 GitHub Actions。

## 广告

当前版本不展示广告。`src/ad-service.js` 已提供平台适配边界，后续可以针对目标发行平台实现激励广告和自然断点插屏广告。
